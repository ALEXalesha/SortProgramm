# Сортировщик загрузок

Программа наводит порядок в папке «Загрузки»: раскладывает файлы по категориям и
типам, не трогая чужие папки программ и игр. Есть графический интерфейс (PyQt6),
режим командной строки, безопасный предпросмотр перед перемещением, лог отмены и
опциональная ИИ-классификация имён через DeepSeek.

## Возможности

- **Раскладка по структуре `Категория / Тип / файл`** — например
  `Учёба / Документы / задачи.pdf`.
- **Категория определяется по приоритету:**
  1. ручные правила из `overrides.json` (точное имя файла → категория);
  2. шаблоны `patterns` из `rules.json` (регулярка на имени файла);
  3. ключевые слова из `rules.json` (поиск подстроки в имени, затем в содержимом
     для текстовых файлов `.txt/.md/.csv`);
  4. запасная категория `fallback_category` (по умолчанию `Others`).

  Разбирается имя без служебного номера, который программа приписывает при
  конфликте (`отчёт (1).pdf` → `отчёт.pdf`), — иначе она сама себе ломает
  раскладку при следующем переразложении.
- **Шаблоны имён** ловят то, что не выразить подстрокой. Рендеры Blender
  называются диапазоном кадров (`0001-0250.mp4`) и едут в `3D`, а не в видео;
  скачанные ролики с датой вместо имени (`0606.mp4`) — в `Медиа`; снимки экрана
  и пересланные фото узнаются по дате в имени.
- **Переразложение** (флаг `--deep`, галочка «Переразложить старое»): программа
  проверяет заново и то, что сама уже разложила, — чтобы новые категории и
  шаблоны применились к старым загрузкам. Подробнее — раздел ниже.
- **Программа двигает только своё.** Чужие папки — распакованные архивы, миры
  игр, репозитории, каталоги программ — не переносятся и не разбираются ни в
  одном режиме.
- **Глубину сканирования задаёт галочка, а не кнопка.** И «🧹 Очистить», и
  «✨ ИИ» смотрят только в корень загрузок; галочка «Переразложить старое»
  (`--deep`) добавляет обеим разрешённые папки (`managed_folders`) рекурсивно.
  Раньше ИИ всегда уходил вглубь, и на разобранной папке это било дважды:
  запрос раздувался с десятка имён до тысячи, а правила для уже разложенных
  файлов оседали в `overrides.json` и перетасовывали папки, которые никто не
  просил трогать.
- **Сухой прогон (dry-run):** план показывается до перемещения, ничего не двигается
  без явного подтверждения / `--apply`.
- **Разрешение конфликтов имён:** при совпадении добавляется суффикс ` (1)`, ` (2)`…
  На классификацию этот суффикс не влияет: `отчёт (1).pdf` разбирается как
  `отчёт.pdf`. Иначе переразложение уносило бы в `Others` файл, который программа
  сама же переименовала.
  Свободное имя проверяется дважды: при построении плана и ещё раз прямо перед
  перемещением. Между «Очистить» и «Применить» проходит сколько угодно времени, и
  за это время имя в целевой папке могло стать занятым — руками, второй копией
  программы, докачкой браузера. `shutil.move` такой файл затирает молча, а папку
  с тем же именем принимает за место назначения и кладёт файл внутрь неё. Если
  имя занято, файл кладётся рядом под свободным, и окно (CLI — строкой в выводе)
  об этом сообщает: план обещал другое.
- **Лог отмены:** каждое применение пишет `.sorter/undo_YYYYMMDD_HHMMSS.json` в папке
  загрузок; функция `undo()` возвращает файлы на места. Если исходный путь к
  моменту отката снова занят, файл возвращается рядом под свободным именем, и
  окно об этом предупреждает: молчаливый «успешный» откат, после которого данные
  лежат под другим именем, — худший из исходов. Номер при этом ставится по
  природе возвращаемого, а не занявшего место: видео, упёршееся в папку
  `клип.mp4`, вернётся как `клип (1).mp4`, а не `клип.mp4 (1)` — иначе
  расширение перестаёт быть последним и файл не открывается. Две сортировки в одну секунду
  получают разные имена (`…_2.json`): затирать прошлый лог значит терять
  возможность откатить ту сортировку. Когда двигать было нечего, лог не пишется
  вовсе — пустая запись в истории ничего не откатывает.
- **История перемещений:** кнопка «🕘 История» в окне показывает список прошлых
  сортировок (дата, число файлов); при клике на запись видно, какие файлы и куда
  переместились. Любую сортировку можно откатить — файлы возвращаются на исходные
  места, а запись убирается из истории. Если что-то вернуть не удалось (файл
  держит другая программа, исходной папки больше нет, диск сняли), запись
  остаётся в истории с теми файлами, которые ещё не вернулись, — чтобы попытку
  можно было повторить. Испорченный журнал (оборванная запись, правка руками)
  отмену не роняет: программа говорит, что откатывать нечем, и остаётся живой.
- **Чистка пустых папок** после перемещения внутри управляемых каталогов — и
  после отката тоже. Откат опустошает ровно те же папки, которые наполнила
  сортировка, но раньше за собой не убирал: файлы возвращались на места, а
  каркас из папок программы оставался стоять, и отмена выглядела сделанной
  наполовину. Чужие папки не сносятся ни в том, ни в другом случае, даже пустые.
- **Вынос 3D-моделей** (`3mf/obj/stl/gcode`) во внешнюю папку, с раскладкой по
  подпапкам расширения (`All_3d/gcode/`, `All_3d/3mf/` и т.д.). В окне — галочка
  «3D-модели → отдельная папка», она же и запоминается в `config.json`. CLI без
  флагов берёт её значение оттуда же, `--to3d` / `--no-to3d` перебивают вручную:
  консоль и окно на одних настройках должны показывать один и тот же план, иначе
  проверять правила через консоль бессмысленно.
- **Автоматический разбор внешней папки 3D:** при каждой сортировке файлы,
  лежащие в корне `All_3d`, раскладываются по подпапкам расширения — по любому
  расширению (`png → png/`, `txt → txt/`), только корень, без ИИ. Это происходит
  всегда, когда путь `external_3d.path` задан, даже если в загрузках менять нечего.
- **ИИ-классификация** (опционально): DeepSeek по списку имён возвращает
  категории, которые сохраняются в `overrides.json`. Запросы уходят пачками
  по 40 имён, ответ «не знаю» правилом не записывается (см. ниже).

## Что программа двигает, а что нет

Двигаются только файлы и только внутри того, что программа создала сама:
корень загрузок плюс её собственные папки-категории из `managed_folders`.

**Чужая папка — это единица, а не набор файлов.** Мир Minecraft, git-репозиторий,
распакованный мод: без соседей `level.dat` или `.git/HEAD` — мусор. Разложив их
содержимое по типам, программа уничтожила бы папку, и собрать её обратно можно
было бы только руками. Поэтому такие папки не переносятся и не разбираются
никогда, ни с ИИ, ни без.

Обход помнит, где уже был, — по настоящему пути папки, а не по тому, каким в
неё пришли. Стык Windows (junction) на папку-предка `iterdir` проходит как
обычную папку, и переразложение заворачивалось в петлю: один файл попадал в
список заново на каждом витке, под путями `Медиа/Videos/Медиа/Videos/…`, пока
Windows не упирался в предел длины пути. Все витки — один и тот же файл,
поэтому план получался такой: первое перемещение переименовывало лежащий на
месте файл в `клип (1).mp4`, следующее уже не находило его и падало, и так
шесть десятков раз. На последнем витке `is_dir()` не отвечал, и сам стык
уезжал в список файлов — то есть переносилась целая папка.

### Переразложение

Обычная уборка («🧹 Очистить», CLI без флагов) трогает только файлы в корне
загрузок: разложенное не ворошится, иначе каждый запуск двигал бы всё подряд.

Галочка **«Переразложить старое»** (`--deep`) включает разбор папок программы:
уже разложенные файлы проверяются заново по текущим правилам. Это нужно после
появления новых категорий или шаблонов — иначе они действуют только на новые
загрузки.

Кнопка «✨ ИИ» слушается той же галочки: без неё модель получает только новые
файлы из корня, с ней — ещё и всё разложенное.

В предпросмотре у каждой строки видно **чем** выбрана категория:

| Пометка | Что значит |
|---|---|
| `правило` | точная запись из `overrides.json` |
| `шаблон` | регулярка из `patterns` |
| `слово` | ключевое слово из `categories` |
| `не опознан` | ничего не подошло, едет в `Others` |

При переразложении это важнее, чем «куда»: по пометке сразу видно, сработало
новое правило или сработала старая запись в `overrides.json`. Просматривать
стоит в первую очередь строки `слово` и `не опознан` — именно там прячутся
ошибки вроде «деталь `Puck_Launcher.step` уехала в Игры по слову launcher».

## Установка и запуск

Требуется Python 3.10+.

```bash
pip install -r requirements.txt
```

```bash
# Графический интерфейс (по умолчанию, PyQt6)
python main.py

# Старый интерфейс на Tkinter
python main.py --tk

# CLI: только показать план (ничего не перемещает)
python main.py --path "C:/Users/User/Downloads"

# CLI: применить перемещения
python main.py --path "C:/Users/User/Downloads" --apply

# Вынести 3D-модели во внешнюю папку (см. external_3d в config.json).
# Без флага берётся галочка из config.json, --no-to3d выключает разово.
python main.py --apply --to3d

# Переразложить уже разложенное по новым правилам
# (сначала без --apply — посмотреть план и причины)
python main.py --cli --deep
python main.py --cli --deep --apply
```

Окно открывается только при запуске без флагов (или по `--tk`). Любой из
`--path`, `--cli`, `--apply`, `--deep`, `--to3d` / `--no-to3d` означает разовый
прогон в консоли: в окне для всего этого есть поля и галочки, а флаг, меняющий
файлы на диске, терять нельзя.

## Конфигурация

Настройки разнесены по двум файлам намеренно. **`rules.json`** — правила
раскладки, их поставляет программа и обновляет при каждой установке.
**`config.json`** — настройки пользователя (пути), их программа пишет сама и при
обновлении не трогает.

Раньше всё лежало в одном `config.json`, помеченном в установщике «не
перезаписывать» — чтобы не стереть пути. Побочный эффект: новые категории не
доезжали до уже установленной копии никогда. Если `rules.json` рядом нет,
правила читаются из `config.json` — старые установки продолжают работать.
В этом случае сохранение из окна их не выбрасывает: пока `rules.json` не
появился, копия в `config.json` — единственная, и первое же закрытие окна
оставило бы программу вовсе без категорий.

- **`rules.json`** — правила раскладки:
  - `categories` — словарь `категория → список ключевых слов` (порядок задаёт
    приоритет: первая подошедшая категория выигрывает); слова, начинающиеся с
    точки (`.exe`, `.json`), считаются расширениями и по содержимому файла
    не ищутся;
  - `patterns` — словарь `категория → список регулярок` на имени файла;
    проверяются раньше ключевых слов, битые выражения молча пропускаются;
  - `category_hints` — короткое описание каждой категории; уходит в промт ИИ,
    чтобы модель не путала соседей вроде «Программы» и «Код»;
  - `type_map` — словарь `тип → список расширений` (например `Документы → pdf, docx`);
    регистр не важен с обеих сторон: `PDF` и `pdf` — одно и то же. Раньше
    сравнение шло с приведённым к нижнему регистру расширением против списка
    как есть, и `"Documents": ["PDF"]` молча переставало совпадать — документы
    уезжали в `Misc` без единой жалобы;
  - `managed_folders` — папки, которые программа считает своими и разрешает
    обходить, на любой глубине; всё остальное чужое и не трогается;
  - `ignore` — маски имён, которые пропускаются (`fnmatch`);
  - `fallback_category`, `fallback_type` — значения по умолчанию.
- **`config.json`** — настройки пользователя:
  - `downloads_path` — какую папку сортировать;
  - `external_3d` — `{ "enabled": ..., "path": ..., "extensions": [...] }`:
    `enabled` — состояние галочки «3D-модели → отдельная папка», её же по
    умолчанию берёт CLI; `path` — внешняя папка 3D (`All_3d`), которая всегда
    разбирается по расширениям; `extensions` — какие расширения из загрузок
    выносить туда. Если `extensions` в файле нет, подставляется `3mf/obj/stl/gcode`
    и дописывается при сохранении: окно про этот ключ не знает, а без него
    настройка выглядит рабочей, но не выносит ничего. `path` не строкой
    (правка руками, съехавшая замена) сбрасывается в пустой — раньше на этом
    программа не открывалась вовсе, то есть починить настройку было уже нечем.

  Незнакомые ключи в `config.json` сохранение из окна не стирает — ручная правка
  переживёт нажатие «Применить».

  Испорченный `config.json` запуск не блокирует. Программа переписывает его при
  каждом закрытии окна, и оборванная запись не должна оставлять пользователя со
  стеком вместо окна: тогда даже путь поправить нечем. Берётся папка загрузок по
  умолчанию, а о проблеме окно предупреждает при старте. В CLI то же
  предупреждение печатается перед планом: нечитаемый `rules.json` означает
  раскладку «всё в `Others`», и увидеть это надо до `--apply`, а не после.
  Несуществующую папку CLI тоже называет вслух (`Папка не найдена: …`) — иначе
  опечатка в `--path` выглядит как «Найдено к перемещению: 0», то есть ровно
  как уже прибранные загрузки. То же самое говорят оба окна, включая старое на
  Tkinter: раньше оно единственное молчало и про испорченные настройки, и про
  ненайденную папку, показывая пустой план как нормальный результат.
- **`overrides.json`** — точные сопоставления `имя файла → категория` (ручные или
  от ИИ); имеют наивысший приоритет. Категория — строка: запись вроде
  `"отчёт.pdf": 3` пропускается с предупреждением, потому что значение отсюда
  уходит прямо в путь и роняло построение плана целиком.

Правку руками файлы переживают: раздел не того типа (`categories` списком
вместо объекта, список слов строкой) пропускается с жалобой в
предупреждении, а не роняет программу и не раскладывает файлы наугад.
Список слов строкой особенно коварен — он перебирается по буквам, и каждая
работает как ключевое слово: раскладка получается неверной молча.

Имя категории и имя типа — это имена папок, и путь вместо имени отбраковывается
с жалобой. Причина в том, как устроен `Path`: абсолютный кусок отбрасывает всё
слева, то есть `Загрузки / "C:/Windows/Temp" / тип` — это просто
`C:\Windows\Temp\тип`. Вписанный не туда полный путь (или `..`) молча уносил бы
файлы из загрузок неизвестно куда, а программа отчитывалась бы об успешной
сортировке. Проверка касается ключей `categories`, `patterns`, `type_map`,
значений `fallback_category` / `fallback_type` и категорий из `overrides.json`.
Вложенная категория (`Учёба/2026`) — обычное дело и работает как раньше.

> ⚠️ Правила стоят выше всего остального, поэтому запись `файл → Others`
> навсегда закрывает файлу дорогу в любую новую категорию. Ответы ИИ «Others»
> поэтому правилом не сохраняются: «не знаю» — это не решение, а файл и так
> уедет в `Others`, но уже по текущим правилам. Поставленные руками правила
> фильтр не трогает.
>
> Имя запасной категории берётся из `fallback_category`, а не пишется в коде
> буквально. Раньше выдумку модели разбор ответа заменял строкой `Others`
> жёстко, и стоило переименовать `fallback_category` — фильтр «не сохранять
> незнание» переставал совпадать по имени, а в `overrides.json` уезжало
> правило `файл → Others`. Категории с таким именем в правилах уже нет, в
> `managed_folders` тоже, значит папка `Загрузки/Others` больше никогда не
> разбирается и не убирается.

### Категории по умолчанию

`Учёба`, `Документы`, `Нейросети`, `Код`, `Электроника`, `3D`, `Игры`, `Дизайн`,
`Программы`, `Медиа`, `Скриншоты`, запасная `Others`.

Порядок в `config.json` — это приоритет, и он продуман:

- `Учёба` **выше** `Документов`: школьные слова (`экзамен`, `демоверсия`,
  `олимпиад`) выигрывают первыми, бумаги забирают остаток;
- `Электроника` **выше** `Программ`, иначе слово `driver` забирает драйвер
  платы CH340 себе;
- `Медиа` **ниже** `Программ`, иначе слово `music` уводит установщик
  `Yandex_Music_x64.exe` из программ в музыку.

Переставляя категории местами, проверь эти три случая — на каждый есть тест
(`tests/test_documents_category.py`).

**`Документы`** — личные бумаги: договоры, соглашения, справки, анкеты,
квитанции, страховки. Появилась потому, что слово `soglashenie` стояло в
«Учёбе» и затягивало туда договоры, а те затыкались правилами `→ Others`.
Когда для файла нет правильной полки, правило-заплатка прячет его в `Others`
вместо того, чтобы починить причину.

В собранном `.exe` (PyInstaller onefile) `config.json` и `overrides.json` лежат рядом
с исполняемым файлом — их можно править без пересборки.

## ИИ-классификация (DeepSeek)

Используется OpenAI-совместимый эндпоинт DeepSeek (`deepseek-chat`). Что уходит
в запрос помимо имён:

- **описания категорий** из `category_hints` — без них модель судит по одному
  названию и путает «Программы» с «Кодом», «Дизайн» с «3D»;
- **пример ввода и ответа** — задаёт формат и разбирает случаи, где модель
  ошибается сама (рендер по диапазону кадров, шрифт Lora против LoRA);
- **папки с косой чертой на конце** (`fluga/`) — чтобы модель оценивала папку
  целиком, а не искала расширение, которого нет. При разборе черта снимается.

Список режется на пачки по 40 имён: на длинных списках модель отвечает не про
все файлы или обрывает ответ. Упавшая пачка не топит остальные — её имена
останутся без правила и поедут по обычным ключевым словам.

Спрашивают модель ровно про то же, что разбирает обычная уборка: по умолчанию
только про корень загрузок, а с галочкой «Переразложить старое» — и про уже
разложенное. Пустое поле пути кнопка отбивает отдельно: `Path("")` — это
текущая папка, и `is_dir()` на ней отвечает True, поэтому без явной проверки
ИИ разбирал папку самой программы, а ответы записывались правилами.

Ключ берётся из:

1. переменной окружения `DEEPSEEK_API_KEY`, либо
2. файла `deepseek_key.txt` рядом с программой.

Файл читается в любой кодировке, которую предлагает Блокнот: UTF-8, «UTF-8 с
BOM» (метка снимается — иначе она уезжала в заголовок запроса, и DeepSeek
отвечал «неверный ключ») и UTF-16. Файл, который не разобрать ничем, значит
«ключа нет»: окно скажет, куда его положить.

> ⚠️ `deepseek_key.txt` — секрет. Он внесён в `.gitignore` и **не** попадает в
> репозиторий и сборки. Не коммитьте ключи.

`tests/test_bugfixes.py` и `tests/test_robustness.py` — воспроизведение

расширением), занятое имя в цели (затёртый файл, файл внутри одноимённой
папки), ручные подпапки, битый JSON, не тот тип внутри `rules.json` и
`overrides.json`, нечитаемая папка, слова-расширения в тексте файла, две
сортировки в одну секунду, пропавший список расширений 3D, служебный
номер ` (1)` в имени, расширения заглавными в `type_map`, испорченный журнал
отмены, пустые папки после отката, путь, вписанный вместо категории, петля из
стыка Windows внутри управляемой папки, переименованная запасная категория в
разборе ответа ИИ и ключ DeepSeek, сохранённый Блокнотом в UTF-16.

`tests/test_ui_ai.py` проверяет кнопку «✨ ИИ» в окне PyQt: окно поднимается в
offscreen-режиме, `_AiWorker` подменён заглушкой, в сеть никто не ходит.
Проверяется, про какие файлы спрашивают модель (корень или всё, по галочке) и
что пустое поле пути отбивается до запроса. Остальное в окнах тестами не
покрыто: `tk.Tk()` требует экрана. Правки в `ui.py` проверяются запуском вживую.

`tests/test_config_split.py` следит за границей правил и настроек — в том
числе за тем, что правила из старого `config.json` переживают сохранение.

`tests/test_cli.py` следит за тем, чтобы консоль не расходилась с окном:
предупреждения о непрочитанных настройках, сохранённая галочка 3D,
несуществующая папка — и за тем, что флаги консоли до неё доезжают, а не
теряются по дороге в окно.

Отдельно `tests/test_real_config.py` проверяет **поставляемый** `config.json`:
порядок категорий и списки слов решают не меньше кода, а каждый случай там —
настоящий файл из загрузок, на котором переразложение однажды ошиблось.

## Сборка

- **Один .exe:** PyInstaller по `Сортировщик.spec`:
  ```bash
  pyinstaller Сортировщик.spec
  ```
- **Установщик Windows:** `installer.iss` (Inno Setup).

Артефакты сборки (`build/`, `dist/`, `release/`, `*.exe`, `*.zip`) в репозиторий не
коммитятся — они регенерируются из исходников.

## Архитектура и принципы

- **Ядро без побочных эффектов до `--apply`:** сканирование и планирование чистые,
  перемещение — отдельный шаг с логом отмены.
- **ИИ изолирован:** сетевой вызов отделён от разбора ответа, чтобы разбор можно было
  тестировать без сети.
- **Консервативность:** программа никогда не заходит в неразрешённые папки и не
  перемещает файл, который уже на нужном месте.
- **Программа двигает только своё:** источником перемещения может быть файл в
  корне загрузок или в папке, которую она сама создала. Чужая папка — единица,
  а не набор файлов; разложив её содержимое по типам, программа уничтожила бы
  её целиком.
- **План объясняет себя:** рядом с каждым перемещением видно, чем выбрана
  категория. Без этого переразложение сотни файлов пришлось бы принимать на
  веру.
- **Испорченные настройки не роняют программу.** `config.json`, `rules.json` и
  `overrides.json` программа пишет сама, значит оборванная запись — обычное
  дело. Любой из них читается «как получится», о проблеме окно предупреждает
  при старте, но запускается. Стек вместо окна оставляет пользователя без
  единственного способа починить настройки. Проверяется не только «читается
  ли файл», но и тип каждого раздела: до `Path()` и до `.items()` доезжает
  либо то, что там ожидают, либо ничего.
- **Потеря возможности откатить — это ошибка.** Если журнал отмены записать не
  удалось, `apply` не молчит: перемещения уже прошли, и снаружи всё выглядит
  как обычная успешная сортировка.
